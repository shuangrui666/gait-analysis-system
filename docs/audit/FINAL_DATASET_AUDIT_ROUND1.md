- `data/raw/README.md`

- 远端原始 ZIP 已确认存在：0/39

“远端未找到”不等于“原始数据已经丢失”；不能据此删除登记记录。

## 4. 哈希映射核验边界

- 39 条记录均有 64 位十六进制 SHA-256 字符串。
- 映射表的状态字段均为 `verified_from_sha256_manifest`。
- 但由于 GitHub `data/raw/` 没有原始 ZIP，本轮无法对任何一组重新计算 SHA-256。
- 因此本轮只能确认“映射表记录格式完整”，不能确认“远端原始文件与哈希匹配”。

哈希映射中的 `source_file_count` 显示，16 个数据集存在多个同内容来源文件记录。副本数量不能直接当作独立实验重复次数；需回到原始文件逐一比对哈希并确认。

## 7. 正式纳入决定

本轮不将任何数据集改为正式纳入或排除。审查矩阵的 `final_inclusion_status` 仍全部为 `not_final`，这是正确且诚实的状态。

原因：
1. 39 份原始 ZIP 当前未在远端 `data/raw/` 找到；
2. 哈希无法从远端原始文件复算；
3. 部分动作标签和采集过程仍需原始元数据/实验记录/视频交叉核实；
4. 多个数据集存在放置过渡、手持姿态变化、动作混合或重复副本风险；
5. 正式纳入必须基于明确的质量门槛，而不是仅凭候选标签。

## 8. 下一步阻塞项

1. 找回或重新提供 39 组原始 ZIP（可先提供压缩包分批上传）。

7. 最后才逐条作出纳入、排除或待定决定。

- 不要删除探索性、失败或被排除的数据；应保留并记录原因。
